# Backend development

Supabase CLI 2.120.0 is pinned in `package.json`. Configuration was generated by the CLI in the original backend repository and imported here. No migrations or custom schema exist yet.

## Hosted connection (creation currently on hold)

1. Obtain founder authorization for the organization, project, and current cost. Do not create a project while the hold remains.
2. Create a dedicated development project. Keep default email verification enabled; review Auth provider, Site URL, and allowed redirects before implementing login.
3. Copy the project URL and modern publishable key into the ignored root `config/supabase.local.json`; use `config/supabase.example.json` as the shape.
4. Run Flutter with `--dart-define-from-file=config/supabase.local.json` and verify the intended Auth endpoint. Initialization alone is not proof of a network connection.
5. Run a database test query through an authorized server-side connection; record only the result, never its credentials.
6. Begin the Stage 2 account migrations and real cross-family access tests.

Use [official Flutter setup](https://supabase.com/docs/guides/getting-started/quickstarts/flutter) and [client initialization](https://supabase.com/docs/reference/dart/initializing). The client only accepts a modern publishable key; do not paste a service-role/secret key into any Dart define. Those values are visible in compiled web output.

## CLI and future migrations

```powershell
cd backend
npm ci
npm run supabase -- --version
npm run supabase -- --help
```

Discover subcommand options with `--help`. Create migration filenames through `supabase migration new`, track SQL in this repository, and apply only to the explicitly selected development target. Keep database passwords/access tokens outside Git. Never run a reset or production push as a routine verification step.

Hosted Supabase use does not require local Docker. Replaying/testing the entire stack locally does; Docker installation was declined. The CLI-generated config is a starting template and still needs review before implementing auth. No app security guarantee follows from the template.

Keep backend implementation progress in the root `docs/STATUS.md`. Do not create a competing roadmap here. AI remains disabled until its approved stage.
